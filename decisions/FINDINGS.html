Can Vowpal Wabbit replace Jev? — running findings

The question: can a VW model answer Jev-style decisions (yes/no, pick one, score on a scale) well enough for low-stakes product use (e.g. routing a query to an LLM tier)? Two bars:

  1. Zero-shot: a pre-trained model reads a new schema and is usable as-is.
  2. Cold start + feedback: usable-ish on day one, then improves quickly from product feedback (corrections, or just “that was right/wrong”).

Data

Name What it is Use
BEV Decision Mix (avbiswas/bev-decision) Third-party set of ~276k texts / 502k questions rebuilt from public datasets into Jev’s CHOICE / NOUL / SCORE format. 28 domains. License listed as “unknown”. Train, dev, seen-domain test
fast-decisions (fastino/fast-decisions) Fastino’s published dev split of their GLiNER2.5-Decide benchmark: 17 domains × 100 texts, 2,900 questions. Synthetic, long, deliberately tricky. Lockbox (see below): never trained or tuned on

What the lockbox is

“Lockbox” is our name for a test set that is locked away during development. We never train on it, and we never use it to choose settings. We only open it to measure a finished model. This is the fairest test of the zero-shot bar, because nothing about it leaked into how VW was built. BEV’s dev split can’t fully play that role: we looked at dev scores while choosing features, so dev is slightly tuned-on.

Our lockbox is Fastino’s fast-decisions set:

  • Who made it: Fastino, the GLiNER2.5-Decide team, as a benchmark of their own. It is unrelated to BEV, so its writing style, schemas and label names are new to VW.
  • Size:
    • 17 domains, 100 texts each, 1,700 texts in all.
    • 2,900 questions: 1,900 choice, 700 yes/no and 300 multi-label.
  • What it looks like:
    • The domains are product-style tasks: email triage, ticket routing, banking intent, clinic requests, restaurant reviews, sports recaps and so on.
    • The texts are synthetic and fairly long, with a median of 750 characters.
    • Many options are bare labels with no description. For example, ticket routing picks a queue from billing_disputes, refunds, shipping, returns, identity and payments.
  • The 2,600 figure: it counts the 2,900 questions minus the 300 multi-label ones, which the OpenAI API can’t answer.
  • No overlap with BEV: 76 BEV texts that share an 8-word sequence with a lockbox text were removed.

The lockbox learning curve (below) is the one place where VW learns from lockbox texts. Even there, each run learns from half of a domain’s texts and is scored on the other half. Every adapted model is then thrown away, so the lockbox stays unused for building or tuning the main model.

Splits (src/vwjev/splits.py): the 28 BEV domains are grouped into 4 folds. For fold k, dev = BEV test rows from the fold’s domains (never trained on: the zero-shot number), train = BEV train rows from the other domains, seen_test = BEV test rows from training domains. No text crosses splits; 76 BEV texts sharing an 8-word sequence with the lockbox were dropped.

Metric

Macro-F1, pooled per domain over (question name, answer) classes, then averaged across domains (src/vwjev/metrics.py). Accuracy is reported alongside. “random” = uniform random choice among the offered options.

Model

VW --csoaa_ldf mc: one line per option, the model scores each option against the shared text/question features, lowest score wins.

What this says so far

  • Word-pair features don’t transfer. Text-word × option-word weights help on domains seen in training but add nothing zero-shot, and hurt on the lockbox. This matches the toy test: learned crosses memorize.
  • All zero-shot signal comes from generic features (overlap between option words and the text, relative to the other options; position on a scale). These get the lockbox from 0.18 (random) to 0.26. That is not usable.

Verdict on headline 1 (zero-shot): no-go

Averaged over held-out domains, zero-shot VW is no better than random macro-F1, and the lockbox (0.29–0.30 vs 0.18 random) is far from usable. Only routing-style domains with label words that appear in the text get well above random, and even those (0.56–0.58) are short of a product bar. Every VW-native lever tried (interactions, IDF/relative overlap, low-rank --lrq) left zero-shot within a few points of these numbers. Moving on to headline 2: cold start + feedback.

Data and metric gotchas found

  • The BEV mix leaks answers through option order. The right answer is listed first far more often than chance in several domains (Support and intent routing 47% vs 20% expected; Trap and adversarial reading 54% vs 22%; Civic and safety 44% vs 22%). Options are now shuffled for training and BEV evaluation, except score scales, whose order carries meaning. The lockbox shows no such bias (17% vs 17%) and keeps its original order.
  • Pooled macro-F1 is unstable with one-off classes. Some domains contain many single-row questions; a lucky guess scores F1 = 1 on each. An untrained model reached 0.863 macro-F1 at 44% accuracy in the Tool domain. Classes with fewer than 5 gold examples are now left out of the macro average (they still count toward accuracy).

VW gotchas found (9.11.9, Python bindings)

  • --csoaa_ldf / --wap_ldf segfault when predicting on multi-line examples with no labels (any variant tried, with or without a shared line). Workaround: give every option a dummy i:0 cost when predicting.
  • With --csoaa_rank, predict() returns scores shifted by one: the shared line is counted as an action (first value always 0.0, last option dropped). Likely VW core, not the Python wrapper. Read each option’s get_partial_prediction() instead (input order, lower = better).
  • Reloading a model with an extra -q (-i model.vw -q fl) silently drops the model’s saved interactions. Restate them (feedback.load_pretrained does this).
  • All three have standalone demos in bug-repros/ (see its README).
  • --probabilities output is very flat (0.58 max on a perfectly separable toy), so confidence must be calibrated separately.
  • A --csoaa_ldf model can’t be loaded with --cb_adf / --cb_explore_adf (“model content is corrupted”). Bandit feedback is therefore turned into csoaa_ldf updates in Python.
  • --cb_adf allows only one costed option per example.
  • With all costs 0/1, csoaa_ldf mc trains as a classifier with ±1 targets; other costs switch it to plain regression, so keep feedback updates 0/1.
  • Interactions can be added when reloading a model (-i model.vw -q fl); a fresh namespace starts at zero weight and learns from new data.
  • System Python 3.10 has no venv/ensurepip; the project uses uv.

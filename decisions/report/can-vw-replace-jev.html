Vowpal Wabbit decision-model study · OpenAI runs 19–20 Oct 2026

Can VW replace Jev?

Jev-style decision models answer yes/no, choice and score questions about a text, from a schema they have never seen. We tested whether Vowpal Wabbit (VW), a fast linear learner, can do that job. We compared it with OpenAI's Decisions API on the same questions.

Short answer

  • Not as a drop-in replacement. On domains it has not trained on, VW scores about as well as random guessing. OpenAI, with no training at all, scores and macro-F1 on the two unseen sets.
  • Close behind, as an in-domain learner. Trained on a domain's own labeled data, VW gets within reach of OpenAI but stays behind it ( vs ). It runs at about half a millisecond per question on a laptop-class CPU, at no per-call cost.
  • With feedback, only for some tasks. Tasks that hinge on keywords or a dataset's own labeling habits learn fast. Spam goes from 0.51 to 0.91 after 100 corrections, level with OpenAI, and to 0.95 after 400. Judgment and reasoning tasks stay far below OpenAI even after 3,200 corrections.
  • As a cheap first tier behind OpenAI, sometimes. Starting with no labels, VW can learn from OpenAI's answers and take over the texts it is confident about. For spam-like tasks it takes most of the traffic with no quality loss. For judgment tasks it takes almost none. It pays for itself only at sizeable volume (see "Cold start").

When VW is good enough

"Good enough" here means usable for low-stakes decisions, like routing a query to a cheaper or stronger LLM.

Cold start: OpenAI first, then VW

This simulates a product that starts with no labeled data. At first every text goes to OpenAI, and VW learns from OpenAI's answers in the background. Later VW answers the texts it is sure about, and the rest still go to OpenAI. We ran it on the 7 BEV domains VW never trained on, with – texts per domain arriving in random order, 3 different orders each. True labels are used only to score what users received, never for training.

    Cost and speed

    OpenAI charges $0.10 per million input tokens. Server time comes from OpenAI's response headers and excludes the network. VW time is for scoring only, measured single-threaded on the 4-core test machine.

    How this was measured

    Data. The BEV Decision Mix (avbiswas/bev-decision) is a third-party collection of about 276,000 texts and 502,000 questions in Jev's question format, across 28 domains. The lockbox is Fastino's fast-decisions dev split: 17 domains × 100 texts. It is a separate, synthetic and deliberately tricky set, and was never used for training or tuning.

    Splits. BEV's domains are split into 4 folds. In each fold, VW trains on three quarters of the domains and is tested on the held-out quarter (out-of-domain) and on unseen texts from its training domains (in-domain). The OpenAI comparison uses fold 0.

    Metric. Macro-F1 averages the F1 score of each answer class, so rare answers count as much as common ones. It is pooled within each domain, then averaged over domains. Classes with fewer than 5 examples are left out. Accuracy is shown alongside.

    Fairness. OpenAI got the same text (cut at 4,000 characters), the same question wording and option descriptions, and the same option order as VW. Multi-label questions were left out because OpenAI's API has no multi-select.

    Caveats.

    • One fold, one model version: OpenAI ran on one fold and one model version (gpt-6-luna, 19 Oct 2026).
    • Bias removed: BEV lists the right answer first far more often than chance, so options were shuffled for every model.
    • English only: the multilingual case is untested.
    • GLiNER2.5-Decide pending: it is set up but not yet run; it needs a machine with more free memory.

    Reproduce it

    Full detail, expected numbers and timings are in REPRODUCE.md in the repo. Every command runs from the repo root.

    1. Install and fetch data

      uv sync
uv run python -I -m vwjev.download     # both datasets, pinned revisions
uv run python -I -m vwjev.data         # unified question format
uv run python -I -m vwjev.splits       # 4 domain folds

    2. Train VW zero-shot models (per fold; fold 0 shown)

      uv run python -I -m vwjev.run --fold 0 --name v5_full_shuf    --vw "-q tl -q ql -q sl -q tp -q qp -q qm"
uv run python -I -m vwjev.run --fold 0 --name v6_generic_shuf --vw "-q sl -q qm -q qp --ignore t"

    3. Score with OpenAI (about $0.50; key in .env)

      uv run python -I -m vwjev.openai_decide --sets lockbox dev seen_test --name luna_f0 --key-file .env --budget 1.2
uv run python -I -m vwjev.openai_report --name luna_f0

    4. Simulate learning from feedback

      uv run python -I -m vwjev.feedback --model runs/v6_generic_shuf --domain "Spam detection"   # one per held-out domain
uv run python -I -m vwjev.lockbox_curve --model runs/v6_generic_shuf --openai luna_f0

    5. Simulate the cold-start cascade (about $0.77 of OpenAI calls)

      uv run python -I -m vwjev.openai_decide --sets stream --name luna_f0 --key-file .env --budget 0.95
uv run python -I -m vwjev.cascade prepare
./scripts/cascade_all.sh
uv run python -I -m vwjev.cascade_report

    6. Collect the numbers and build this page

      uv run python -I -m vwjev.final_report
uv run python -I -m vwjev.build_report_page

    VW issues found along the way

    Each has a standalone demo in bug-repros/ (vowpalwabbit 9.11.9, Python bindings).

    • Crash on unlabeled multi-line predict. --csoaa_ldf and --wap_ldf segfault when predicting on examples without cost labels. Workaround: dummy i:0 costs.
    • Shifted rank scores. With --csoaa_rank, predict() counts the shared line as an option, so the scores are shifted by one. Workaround: read each option's partial prediction.
    • Reloading with a new -q drops the saved interactions. It does so silently. This corrupted our first feedback curves, which were rerun; the conclusions held.
